Минималистичное тёмное портфолио, построенное вокруг типографики. Первый экран — одна короткая фраза и пять текстовых ссылок; ниже — последние коммиты GitHub и две панели телеметрии только для чтения. Интерфейс намеренно тихий: без hero-панелей, карточек, бейджей и декоративных графиков.

## Возможности

- Пять точек входа на главной: разработка, инженерия, GitHub, личность и контакты.
- Лента коммитов GitHub в реальном времени с серверным кэшем на 15 минут и честным состоянием offline.
- Две панели телеметрии только для чтения: основная система и вторичный VPS с трафиком VPN.
- Честные состояния телеметрии: `online`, `demo` и `offline` всегда видны и никогда не смешиваются.
- Мягкая деградация: если бэкенд телеметрии недоступен, сайт продолжает работать, а дашборд показывает `offline`.
- Декоративный фон, управляемый прокруткой: строки кода выезжают из полей страницы и затухают под колонкой текста; отключён при reduced-motion и на узких экранах.
- Генерируемое изображение Open Graph (PNG 1200×630), `robots.txt` и карта сайта.
- Эндпоинт liveness для проверки работоспособности контейнера.
- Серверные компоненты по умолчанию; клиентские границы только там, где нужна интерактивность.
- Только тёмная тема, видимый фокус, поддержка reduced-motion и skip-link.
- Адаптивность вплоть до 375 px по ширине.

## Требования

- Node.js 26 — то, на чём собирается образ контейнера (закреплён `26.12.1-alpine3.24`); сам Next.js 16 требует Node.js 20.9 или новее. Диапазон `engines` в проекте не закреплён.
- npm с закоммиченным `package-lock.json`.
- Для запуска сайта не нужны база данных или внешние сервисы. Телеметрия опциональна.

## Быстрый старт

```bash
npm ci
npm run dev
```

Сайт доступен на <http://localhost:3000>.

Без учётных данных телеметрии дашборд на главной показывает явно помеченные демо-значения в режиме разработки. Продакшен-сборки вместо этого сообщают `offline`.

## Переменные окружения

Для запуска приложения ничего не требуется. Телеметрии нужен доступный экземпляр Beszel и отдельный аккаунт только для чтения.

```bash
cp .env.example .env
```

| Переменная | Нужна для живой телеметрии | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `BESZEL_URL` | да | — | Базовый URL хаба Beszel |
| `BESZEL_EMAIL` | да | — | Email аккаунта только для чтения |
| `BESZEL_PASSWORD` | да | — | Пароль аккаунта только для чтения |
| `BESZEL_SYSTEM` | да | — | Система Beszel для основной панели |
| `BESZEL_DISPLAY_NAME` | нет | Встроенная подпись | Подпись на основной панели |
| `BESZEL_REVALIDATE` | нет | `30` | TTL кэша телеметрии в секундах, ограничен 10–300 |
| `BESZEL_VPS_SYSTEM` | нет | `VPS` | Система Beszel для панели VPS |
| `BESZEL_VPS_DISPLAY_NAME` | нет | `vps · vpn` | Подпись на панели VPS |

`.env.example` содержит только заглушки. `.env` игнорируется Git и никогда не должен коммититься.

| `npm run dev` | Запуск dev-сервера |
| `npm run build` | Продакшен-сборка |

## Телеметрия

`lib/beszel.ts` работает только на сервере. Он авторизуется в Beszel, преобразует записи в компактную форму дашборда и никогда не отдаёт учётные данные или токены в браузер.

- Запросы завершаются по таймауту через 5 секунд.
- Токен доступа кэшируется на 30 минут, с единственным повтором после `401`.
- Ответы телеметрии кэшируются примерно на 30 секунд (`BESZEL_REVALIDATE`).
- Основная панель показывает CPU, RAM, диск, температуру, uptime и сетевой трафик.
- Панель VPS показывает CPU, RAM и диск, а в четвёртом слоте — трафик скачивания/отдачи. Агенты без датчика температуры не дают показаний, поэтому вместо неё показывается трафик.
- Клиент обновляется каждые 30 секунд и приостанавливается, пока вкладка скрыта.

### Состояния

| Состояние | Когда появляется | Что отображается |
| --- | --- | --- |
| `online` | Beszel вернул систему, помеченную как доступная | Живые значения |
| `demo` | Только в разработке, учётные данные не заданы | Примерные значения с явной пометкой |
| `offline` | Нет учётных данных в продакшене или Beszel недоступен | Прочерки либо последний удачный снимок с пометкой `offline` |

Панель VPS никогда не откатывается к демо-значениям.

### API-маршруты

- `GET /api/dashboard` возвращает основной снимок на верхнем уровне и вторичный под `vps`. Ограничение — 60 запросов в минуту на IP, ответ с `Cache-Control: no-store`, без секретов. Ограничитель хранится в памяти и рассчитан на один инстанс.
- `GET /api/health` возвращает `status`, `uptime` и `timestamp`. Не зависит от Beszel и используется как liveness-проба контейнера.

## Контент

`lib/content.ts` — единственный источник правды для текстов, ссылок и проектов сайта.

- Лента коммитов на главной не редактируется вручную: `lib/github.ts` каждые 15 минут читает публичные ветки по умолчанию из `githubOwner` и показывает три последних коммита.
- `project.href: "#"` рендерит название проекта как обычный текст, а не ссылку.
- Социальные ссылки используют `category`, а также флаги `showInHeader` и `showInFooter`; footer и header фильтруют один и тот же массив.
- Добавление маршрута означает создание `app/<route>/page.tsx` и обновление сразу `navLinks` и `modules`.

## Дизайн-система

- Поддерживается только тёмная тема.
- Цвета — RGB-триплеты в `app/globals.css`, смапленные в Tailwind в `tailwind.config.ts`. Используйте семантические классы вроде `bg-background`, `bg-surface`, `border-line`, `text-foreground`, `text-muted`, `text-accent`, `text-positive` и `text-warning` вместо «сырых» hex-значений.
- IBM Plex Sans — основной шрифт; JetBrains Mono зарезервирован для мелких технических подписей.
- `container-page` — стандартная ширина контента; дашборд использует `max-w-[1440px]`.
- Анимации уважают `prefers-reduced-motion`, фокус-ринги остаются видимыми, а интерактивные элементы — настоящие ссылки и кнопки.

## Docker

Образ собирается в три стадии (`deps` → `builder` → `runner`). Рантайм-стадия — минимальный Alpine-образ, содержащий только бинарник Node.js и standalone-сборку — без npm, npx и corepack — плюс разделяемые библиотеки, с которыми линкуется musl-бинарник Node (`libstdc++`, `libatomic`); работает под непривилегированным пользователем на порту 3000. `HEALTHCHECK` проверяет `/api/health` каждые 30 секунд.

```bash
docker build -t portfolio .
docker run --rm -p 3000:3000 --env-file .env portfolio
```

Compose-развёртывание мантейнера не входит в этот репозиторий: оно ожидает уже существующие внешние Docker-сети для обратного прокси и стека телеметрии и читает переменные из `.env`. Поэтому оно не самодостаточно и не запустится на чистой машине без этих сетей. Для локальной работы используйте `npm run dev` или команду `docker run` выше.

## Проверки

```bash
npm run lint
npm run typecheck
npm run build
```

В этом репозитории нет автоматического тест-раннера или CI. Для ручной проверки запустите приложение и просмотрите основные маршруты, `/api/health`, `/api/dashboard`, `/sitemap.xml`, `/robots.txt` и `/opengraph-image`.

## Безопасность

- Держите учётные данные Beszel на сервере. Никогда не используйте для них переменные `NEXT_PUBLIC_*` и не импортируйте `lib/beszel.ts` из клиентского компонента.
- Не коммитьте `.env` и реальные учётные данные. `.env.example` — единственный файл окружения, который должен быть в репозитории.
- Считайте ответы телеметрии недоверенным вводом и проверяйте значения перед отображением.
- Оставляйте в `/api/dashboard` только те поля, которые нужны интерфейсу.
- Используйте отдельный read-only аккаунт Beszel, а не администраторский.
